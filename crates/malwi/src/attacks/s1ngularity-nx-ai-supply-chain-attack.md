# s1ngularity — Nx AI-CLI weaponization (August 2025)

## Carrier
npm packages `nx` (versions 21.5.0, 20.9.0, 20.10.0, 21.6.0, 20.11.0, 21.7.0, 21.8.0, 20.12.0) and `@nx/*` plugin packages (`@nx/devkit`, `@nx/js`, `@nx/workspace`, `@nx/node`, `@nx/eslint`, `@nx/key`, `@nx/enterprise-cloud`), each containing a `telemetry.js` file referenced as a `postinstall` script in `package.json`, executed automatically during `npm install`, `yarn`, or `pnpm install`.

## Technique
The `telemetry.js` postinstall script exits on Windows. On Linux/macOS it checks for `claude`, `gemini`, and `q` on PATH via `which`, then spawns each available AI CLI with danger-bypassing flags and a prompt instructing the agent to recursively search the filesystem for sensitive files. Exact invocation structure:

```
claude --dangerously-skip-permissions -p PROMPT
gemini --yolo -p PROMPT
q chat --trust-all-tools --no-interactive PROMPT
```

The `nx` package uses a generic file-search prompt; the `@nx/*` plugin variants use a targeted prompt listing wallet/secret patterns (UTC--, keystore, wallet, *.key, *.keyfile, .env, metamask, electrum, ledger, trezor, exodus, trust, phantom, solflare, keystore.json, secrets.json, .secret, id_rsa, Local Storage, IndexedDB). After the AI CLI writes `/tmp/inventory.txt`, the malware directly reads every listed file, base64-encodes each, and collects them into `result.inventory`.

## Payload/effect
The malware gathers additional credentials via `gh auth token`, `npm whoami` + `~/.npmrc`, and `process.env` dump. It creates a public GitHub repository named `s1ngularity-repository` (with numeric suffixes -0, -1, etc.) under the victim's account, triple-base64-encodes the collected data, and uploads it as `results.b64` via the GitHub API (`PUT /repos/<full_name>/contents/results.b64`). It also appends `sudo shutdown -h 0` to `~/.bashrc` and `~/.zshrc` as a denial-of-service persistence mechanism.

The initial vulnerable GitHub workflow that enabled the compromise is estimated to have been generated by Claude Code (attacker-toolchain inference, not confirmed evidence). The exact mechanism of initial access to the Nx GitHub repository is not fully documented — only that a vulnerable `pull_request_target` workflow with bash-injection via PR title was exploited to trigger the `publish.yml` pipeline.

## Detectable signal
The shape, which catches a variant sharing no text with this incident:
- an install hook that probes for developer tooling on `PATH` before deciding what to do: a
  `which`/`where`/`command -v` sweep, especially for AI coding agents (`claude`, `gemini`, `q`,
  `cursor`, `copilot`), then spawning whichever it finds
- any invocation of an agent CLI with a flag that disables its confirmation or sandbox
  (`--dangerously-skip-permissions`, `--yolo`, `--trust-all-tools`, `--no-interactive`,
  `--auto-approve`): delegating the filesystem search to a trusted local agent means the malware
  itself never writes the traversal code, so signature matching on the search has nothing to match
- a prompt string embedded in package code that instructs a tool to enumerate secrets, wallets, or
  key material, then write an inventory to a fixed path under `/tmp` which the caller then reads
- credential collection through legitimate CLIs rather than file parsing: `gh auth token`,
  `npm whoami`, `aws configure get`, followed by a `process.env` dump
- exfiltration by creating a repository under the victim's own account and committing the data,
  which is authenticated traffic to a host the stolen token already belongs to
- a shell profile (`~/.bashrc`, `~/.zshrc`, `~/.profile`) appended to by an install script

Literals from this incident, which confirm a replay but will not find a new one:
- `telemetry.js` in a `node_modules` tree, the object key `cliChecks`
- `s1ngularity-repository`, `/tmp/inventory.txt`, `results.b64`
- the flag strings `--dangerously-skip-permissions`, `--yolo`, `--trust-all-tools`
